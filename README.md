# Programming for the Web — Your Journal

Welcome to the team. For the next 8 weeks you're working through the
**Programming for the Web** course, and this repo is how you report your
progress — think of it less like a school folder and more like the way a
junior developer actually works: real tickets, a real commit history, real
evidence of what you did.

## How this works

1. Clone this repo to your own laptop.
2. Each lesson on the course site has a matching **ticket** in
   [`tickets/`](tickets/) — a markdown file with the same name the course
   site's own "⬇ .md" button downloads (e.g. `w1-applications-of-web-programming-notes.md`).
   You can either fill the ticket in directly, or write your notes in the
   course site's markdown editor, download them, and drop the file in over
   the template — either way, the filename should match.
3. When you finish a lesson (or make real progress on one), **commit it**
   with a clear message — like you're reporting to your manager, not just
   satisfying a checkbox. `"Closed W1 — covered all three app types,
   installed airhorner.com as a PWA"` tells me something. `"update"` doesn't.
4. Push regularly, not all at once at the end. Your commit history is the
   actual evidence here — a project with seventeen files added in one commit
   the night before I check doesn't look like eight weeks of work, because
   it isn't.

## What's in a ticket

Every ticket has the same shape:

- **Brief** — what this ticket covers (go read the actual lesson on the
  course site first — this file is where you report back, not where you
  learn the material).
- **Work Log** — your own process, in your own words.
- **Deliverable** — the lesson's exam-style question, and your response to
  it (or a **Build Log** instead, for the couple of tickets that are a
  hands-on build rather than a written question).
- **Sandbox Code** — on lessons with a live code sandbox, paste your final
  version here. The sandbox itself isn't saved anywhere, so this is your
  only record of it.
- **Investigation Notes** — most tickets close with a small set of
  hands-on investigations (open a real site, run a real tool, compare real
  results). These are genuinely meant to take you outside the lesson page —
  budget real time for them, don't rush them the night before.
- **Questions / Blockers** — anything you're stuck on. Use it.

## On AI

Don't use generative AI for any part of this — not the notes, not the
exam-style responses, not the investigations. Two reasons, and only one of
them is about rules:

**First, the practical one.** This repo isn't your grade. The real stakes
are the supervised HSC exam, which no AI can sit for you. If you let it
write your notes here, you arrive at that exam less prepared than if you'd
done the work — a cost you pay yourself, not one you impose on anyone else
in the class.

**Second, the actual reason.** Most people who choose Software Engineering
as a subject do it because they want to build things — the joy of coding
*is* coding, not the mark at the end of it. If that's you, this repo is
just a way to make your own progress visible over time, to yourself as much
as to me. If it isn't you — well, see the first reason.

I'll be checking in on activity across the term. Commit as you go.
